## 11. Risk Assessment

Main risks:

- If adapter files copy safety rules or template content, they can drift from the canonical skill and weaken the safety boundary.
- If indexes are updated before invocation examples, `skills_index.json` may expose an empty or low-quality `invocation_example`.
- If `tools/generate_skill_metadata.py` is run without reviewing its full diff, it may refresh broader `.agents/skills/*.md` summaries and widen the intended scope.
- If F1a updates only one discovery surface, tools may disagree about whether the skill exists.
- If `.codex` is treated as a hub-local skill adapter surface, hub and consumer contracts may be confused. In this repository, `.codex` is config-only; in consumer projects, `.codex/skills` is the project-local runtime skill-content root.

Risk controls:

- Keep adapters thin and reference-first.
- Add invocation examples before or with metadata/index refresh.
- Update `.agents`, `.github`, `skills_index.json`, `SKILLS_INDEX.md`, and `.agents/skills/skills_index.md` together in F1a if implementation is approved.
- Use `check_adapter_consistency.py --mode hub` for hub-local adapter validation.
- Keep `audit_derivative_surfaces.py` report-only unless a separate governance task changes that policy.
