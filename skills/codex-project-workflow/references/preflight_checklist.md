# Repository Preflight Checklist

Complete this checklist before editing. Record only exceptions that affect the task.

- [ ] Identify the repository root, current branch or working context, and working-tree state.
- [ ] Read `AGENTS.md` when present; identify any nested or path-specific instructions.
- [ ] Read `NEXT_ACTION.md`, the active task package or Task Card, and relevant project status or handoff documents when present.
- [ ] Classify the task and restate its objective, authorized paths, forbidden paths, expected output, and stop conditions.
- [ ] Inspect existing conventions in the target area before adding or naming files.
- [ ] Confirm that the requested delta does not require unapproved adapters, indexes, tools, tests, generated outputs, or external actions.
- [ ] Select validation commands proportional to the task and confirm they are available or document why they cannot run.
- [ ] Decide whether a focused readonly sub-agent materially lowers risk; otherwise keep the task with the main agent.
- [ ] Stop and report any contradiction between the task package, local instructions, validation requirements, or authorized paths.

For `evidence-only`, `preflight-only`, and `review-only` tasks, finish preflight without making edits. For implementation tasks, do not begin edits until this checklist is materially complete.
